# Ch04 — Claude에게 잘 지시하는 법

> 이 챕터가 커리큘럼 전체에서 가장 중요하다.
> Claude가 코드를 짜지만, **무엇을 만들지 설계하고 결과를 검증하는 것**은 개발자인 당신이 한다.
> 좋은 요청 하나가 나쁜 요청 10번보다 낫다.

---

## 개념

### 왜 요청 품질이 중요한가

Claude는 문맥이 없으면 가장 일반적인 해석으로 코드를 만든다.
"플레이어 만들어줘"라고 하면 Claude는 수많은 가정을 혼자 결정한다:
- 어떤 Node 타입? CharacterBody3D? RigidBody3D?
- 이동 방식? WASD? 방향키? 조이스틱?
- 카메라는 1인칭? 3인칭?
- 이동 속도는?
- 점프는?

이 가정들이 원하는 것과 다르면 수정 요청을 여러 번 해야 한다.
처음에 명확하게 요청하면 한 번에 원하는 결과가 나온다.

---

### 좋은 요청 vs 나쁜 요청

| 나쁜 요청 | 좋은 요청 |
|----------|----------|
| "플레이어 만들어줘" | "Godot 4에서 WASD로 이동하고 Space로 점프하는 3인칭 CharacterBody3D 플레이어를 만들어줘. 이동 속도 5, 점프력 8, 중력은 9.8" |
| "에러 났어" | "이 에러가 났어: [에러 전체 붙여넣기]. 씬 구조: Player(CharacterBody3D) > MeshInstance3D, CollisionShape3D, Camera3D" |
| "더 좋게 만들어줘" | "플레이어 이동할 때 카메라가 너무 딱딱하게 따라와. lerp로 부드럽게 따라오게 수정해줘. scripts/player.gd 직접 수정해줘" |
| "색 바꿔줘" | "Ground의 MeshInstance3D 색상을 회색(0.5, 0.5, 0.5)에서 초록색(0.2, 0.8, 0.2)으로 바꿔줘. scenes/world.tscn 직접 수정해줘" |

---

### 요청 템플릿

#### 새 기능 요청
```
Godot 4에서 [기능]을 만들어줘.
- 씬 구조: [현재 노드 트리 설명]
- 동작: [어떻게 동작해야 하는지 구체적으로]
- 파라미터: [속도, 크기, 횟수 등 수치]
- 파일 위치: res://scenes/[파일명].tscn, res://scripts/[파일명].gd
- 파일을 직접 작성해줘 (코드 블록만 제시하지 말고)
```

#### 에러 수정 요청
```
Godot 4 에러가 났어:
[에러 메시지 전체 붙여넣기 — Output 탭의 빨간 텍스트 전부]

현재 구조:
- 씬: res://scenes/[파일명].tscn
- 스크립트: res://scripts/[파일명].gd
- 노드 트리: [씬 패널에서 본 구조]

직접 파일을 수정해줘.
```

#### 동작 수정 요청
```
현재: [현재 동작 설명 — 구체적으로]
원하는 것: [바꾸고 싶은 동작 — 구체적으로]
관련 파일: res://scripts/[파일명].gd

파일을 직접 수정해줘.
```

#### 개념 이해 요청
```
[개념/기능]이 어떻게 동작하는지 설명해줘.
초보자 눈높이로 비유를 들어서 설명해줘.
[현재 코드에서 어디에 있는지도 알려줘] (선택)
```

---

### 요청할 때 포함해야 할 정보

**필수 정보:**
1. **Godot 버전**: "Godot 4에서" (GDScript 4.x 문법이 다름)
2. **파일 경로**: "res://scripts/player.gd 직접 수정해줘"
3. **구체적인 수치**: 속도, 각도, 거리 등

**선택 정보 (있으면 훨씬 좋음):**
4. **현재 씬 구조**: 씬 패널의 노드 트리
5. **에러 메시지**: Output 탭의 빨간 텍스트 전체
6. **현재 코드**: 문제가 있는 스크립트 파일 내용

---

### Claude가 직접 할 수 있는 것 vs 에디터에서 해야 하는 것

**Claude가 직접 파일 작성/수정:**
- `.gd` 스크립트 파일 — 언제든지 직접 수정
- `.tscn` 씬 파일 — 노드 구조, 속성, 스크립트 연결
- `project.godot` — 입력 설정, Autoload, 해상도, 메인 씬
- 폴더 구조 생성 — `scenes/ui/`, `assets/audio/` 등

**에디터에서만 가능한 것:**
- `.glb` 3D 모델 임포트 설정 (Claude가 안내해줄 수 있음)
- 애니메이션 키프레임 직접 편집
- 노드 위치를 마우스로 미세 조정
- NavigationMesh Bake (Bake 버튼 클릭)
- **실행** (F5/F6)

---

### 현재 프로젝트 상태 공유 방법

Claude에게 현재 상태를 전달할 때 유용한 정보:

**씬 구조 공유:**
Godot 에디터 씬 패널에서 노드 트리를 텍스트로 설명
```
예: "씬 패널이 이렇게 되어있어:
World (Node3D)
├── DirectionalLight3D
├── Ground (StaticBody3D)
│   ├── MeshInstance3D
│   └── CollisionShape3D
└── Player (CharacterBody3D)
    ├── MeshInstance3D
    ├── CollisionShape3D
    └── CameraPivot (Node3D)
        └── SpringArm3D
            └── Camera3D"
```

**에러 공유:**
Output 탭의 빨간 텍스트 전체를 복사해서 그대로 붙여넣기

**동작 설명:**
"이렇게 되고 있는데" + "이렇게 되어야 해"를 명확히 구분

---

### 반복 작업 흐름 (Iteration Loop)

게임 개발은 아이디어 → 구현 → 테스트 → 수정의 반복이다:

```
1. Claude에게 기능 요청
    ↓
2. Claude가 파일 수정/생성
    ↓
3. Godot에서 F5/F6으로 실행
    ↓
4a. 잘 됨 → 다음 기능 요청
4b. 안 됨 → 에러 메시지 or 동작 설명을 Claude에게 전달
    ↓ (4b 경우)
5. Claude가 파일 수정
    ↓
6. 다시 실행 확인
```

이 사이클을 빠르게 돌리는 것이 핵심이다.
에러가 났을 때 자책하지 말 것 — 에러는 정상적인 개발 과정이다.

---

### 큰 기능을 작게 나누는 법

"3인칭 슈터 게임 만들어줘"는 너무 크다. 이렇게 나눠서 요청한다:

```
Step 1: "기본 플레이어 이동 만들어줘 (WASD, 점프)"
    ↓ 테스트
Step 2: "3인칭 카메라 rig 추가해줘 (SpringArm3D)"
    ↓ 테스트
Step 3: "총 발사 기능 추가해줘 (Raycast, 총구 위치)"
    ↓ 테스트
Step 4: "적 AI 만들어줘 (추격, 공격)"
    ↓ 테스트
Step 5: "HUD 만들어줘 (체력바, 탄약 표시)"
```

각 단계마다 테스트해서 동작을 확인한 후 다음 단계로 넘어간다.
한 번에 너무 많이 하면 에러가 났을 때 어디서 난 건지 찾기 어렵다.

---

### 좋은 Claude 협업을 위한 팁

**1. "직접 파일 수정해줘"를 명시한다**
Claude는 기본적으로 코드 블록을 제시할 수도 있다.
파일을 직접 수정해달라고 명시하면 직접 작성한다.

**2. 파일 경로를 항상 포함한다**
"player.gd"보다 "res://scripts/player.gd"가 명확하다.

**3. 에러 메시지를 잘라내지 않는다**
에러 메시지의 일부만 보내면 원인 파악이 어렵다.
Output 탭의 빨간 텍스트 전체를 복사해서 보낸다.

**4. 결과가 원하는 것과 다르면 구체적으로 설명한다**
"이상해" 보다 "점프 높이가 너무 높아서 화면 밖으로 나가"가 훨씬 좋다.

## 실습

### 실습 4-1: 기본 씬 요청
다음 요청을 Claude에게 그대로 보내서 프로젝트를 만들어본다:

> "Godot 4 프로젝트에 기본 3D 씬을 만들어줘. 파일들을 직접 작성해줘.
> - `res://scenes/world.tscn` 파일로 저장
> - 회색 바닥 (StaticBody3D + PlaneMesh 20x20 + CollisionShape3D)
> - 파란 캡슐 플레이어 (CharacterBody3D + CapsuleMesh + CollisionShape3D, 위치 y=1)
> - 태양광 (DirectionalLight3D, rotation x=-45)
> - Camera3D (위치 y=5, z=8, rotation x=-30로 내려다보는 시점)
> - project.godot의 메인 씬을 world.tscn으로 설정해줘."

Claude가 파일을 만들면 → F5로 실행 → 결과 확인

### 실습 4-2: 수정 요청 연습
4-1에서 만든 씬에서 다음 수정을 요청해본다:

> "현재 world.tscn의 Ground MeshInstance3D 색상을 초록색(0.2, 0.6, 0.2)으로 바꿔줘.
> 직접 파일을 수정해줘."

수정 전후 결과를 비교한다.

### 실습 4-3: 에러 해결 요청 연습
Claude에게 의도적으로 없는 노드를 참조하는 코드를 만들어달라고 요청하고,
나온 에러 메시지를 Claude에게 그대로 보내서 수정 요청하는 것을 연습한다.

## 확인 포인트
- [ ] 에러가 나면 Output 탭의 메시지 전체를 복사해서 전달하는 습관이 생겼다
- [ ] "기능 + 수치 + 파일 위치 + 직접 수정해줘"를 포함한 요청을 할 수 있다
- [ ] 큰 기능을 작은 단계로 나눠서 요청하는 법을 안다
- [ ] 씬 구조를 텍스트로 설명하는 법을 안다
- [ ] Claude가 파일을 직접 수정할 수 있다는 것을 안다
