# Ch06 Q&A

---

## Q1. SpringArm3D가 정확히 뭐야?

**셀카봉이라고 생각하면 된다.**

스마트폰을 봉 끝에 매달아두면, 봉이 벽에 부딪혔을 때 사진에 벽이 안 나오게 봉을 줄여야 한다. SpringArm3D가 그 역할이다.

```
CameraPivot (피벗)
    └── SpringArm3D (셀카봉)  ← 최대 길이: spring_length = 4
            └── Camera3D (스마트폰)
```

- **봉이 벽에 안 닿을 때**: 카메라가 플레이어에서 4m 뒤에 위치
- **봉이 벽에 닿을 때**: 카메라를 자동으로 앞으로 당김 (봉 길이 줄임)

이게 없으면 카메라가 벽 속으로 들어가서 화면이 새까매진다. 3인칭 게임에 거의 필수다.

## Q2. 레이캐스트(Raycast)가 뭐야?

**눈에 보이지 않는 레이저를 쏘는 것이다.**

```
CameraPivot ————레이저————→ 카메라 위치
                    ↑
              여기에 벽이 있으면 감지
```

레이저가 뭔가에 닿으면 "충돌 감지". 닿은 지점까지만 팔을 줄인다.

SpringArm3D는 내부적으로 매 프레임 이 레이캐스트를 쏘면서 "팔 앞에 뭔가 있나?"를 확인한다.

게임에서 레이캐스트는 여러 곳에 쓰인다:
- 총알이 맞는 오브젝트 감지
- 플레이어 앞에 아이템이 있는지 확인
- SpringArm3D의 카메라 충돌 회피 (지금 이 케이스)

## Q3. 착지할 때 왜 카메라가 순간 가까워지나?

**SpringArm3D의 레이캐스트가 플레이어 자신의 몸(CapsuleShape3D)을 장애물로 인식하기 때문이다.**

착지 순간에 이런 일이 벌어진다:

```
[착지 직전]
물리 엔진이 "플레이어 캡슐이 바닥과 겹쳤다"고 판단
→ 플레이어를 위로 살짝 밀어내는 연산 실행

[그 찰나]
CameraPivot에서 쏜 레이캐스트가 플레이어 캡슐에 맞음
→ SpringArm이 팔을 압축 (카메라 가까워짐)

[다음 프레임]
물리 충돌 해소 완료, 레이캐스트가 더 이상 캡슐에 안 맞음
→ SpringArm이 팔을 다시 폄 (카메라 원위치)
```

결과: 착지할 때마다 카메라가 순간 가까워졌다가 풀리는 것처럼 보임.

## Q4. 어떻게 고쳐?

**SpringArm3D에 "이 오브젝트는 무시해" 목록을 추가하면 된다.**

Godot에서 모든 물리 오브젝트는 고유 ID(RID)를 가지고 있다.
SpringArm3D의 `add_excluded_object(RID)`에 플레이어 자신의 ID를 넘기면, 레이캐스트가 플레이어 캡슐을 그냥 통과한다.

```gdscript
func _ready():
    $CameraPivot/SpringArm3D.add_excluded_object(get_rid())
```

- `get_rid()` = "이 노드(Player)의 물리 고유 ID를 달라"
- `_ready()` = 씬이 준비됐을 때 한 번 실행되는 함수 (JS의 `componentDidMount`와 같음)

이걸 추가하면 SpringArm3D가 플레이어 자신을 장애물로 보지 않아서 버그가 사라진다.
